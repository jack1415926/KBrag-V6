# 原始问题文本排名锚定实验

## 1. 结论

保留原始问题文本排名后，融合质量显著改善：Section Recall@5为78.33%，Image Recall@5为67.50%，分别比同轮Vision转文字基线高17.50和12.50个百分点，也高于旧融合的63.33%和54.17%。240条记录完整，错误0、VL Rerank回退0。

预设上线门槛仍未全部通过。新融合P95为52.279秒，高于50秒绝对限制；相对同轮Vision基线20.006秒为2.61倍，高于1.35倍限制。因此代码改动保留，但 `VISUAL_RETRIEVAL_ENABLED=0`继续不变。

## 2. 改动范围

视觉开启时并行保留四类排名：

1. 原始问题 → 现有文本检索，使用原始问题自己的产品路由；
2. 原始问题 + Vision描述/OCR/关键词 → 文本检索；
3. 扩展文本 → 视觉索引；
4. 用户图片 → 视觉索引。

四类候选统一映射到 `产品|Parent Section ID`后进行RRF，再执行VL Rerank。视觉关闭时仍只运行原文本链路，工具Schema和对外API不变。

## 4. 子集

- 派生图：Section Recall@5从54.44%升至77.78%，Image Recall@5从50.00%升至66.67%；
- 手册外写实图：两组Section Recall@5均为80.00%，Image Recall@5均为70.00%；
- AI生成、唯一用户实拍和网络照片子集没有净变化；主要收益来自30张手册派生图。

## 5. 延迟边界

融合三轮P95分别为57.64、63.68、10.67秒；Vision基线分别为48.59、4.67、7.02秒。长尾主要集中在前两轮远程服务时段，第三轮恢复正常。这支持“远端服务或并发竞争造成长尾”的推断，但不改变实际门槛失败：当前观察到的线上P95仍不可接受。

原始文本锚定增加一条Qwen3文本Embedding/Rerank请求，并与扩展文本和视觉召回并发执行。后续若继续优化，应优先缓存重复Query Embedding、限制并发争用或取消重复文本Rerank，而不是降低延迟门槛。
