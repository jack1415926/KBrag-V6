# 源码与运行说明

## 1. 代码包说明

KBrag V6 包含多模态客服智能体的核心源码、RAG 知识库、检索索引、图片 caption、启动脚本和验证材料。

使用者可在独立环境中完成：

1. 安装依赖；
2. 启动 `/chat` RESTful API；
3. 使用 smoke 脚本进行接口验证；
4. 阅读源码与文档复核核心模块。

## 3. 核心模块

| 文件 | 作用 |
| --- | --- |
| `api_server.py` | FastAPI 服务入口，提供 `GET /health` 和 `POST /chat`；在线场景在这里完成 service / tech 分类，并映射为 `fake_qid=0/64` |
| `agent.py` | 智能体主流程，根据 `question_id` 选择客服或技术 prompt；技术题执行产品路由、预检索、`search_manual` 工具调用和答案收束 |
| `request_context.py` | 使用ContextVar隔离请求QID，并统一保存截止时间、取消事件及下游剩余超时 |
| `llm_router.py` | 大模型调用路由，支持 OpenAI-compatible 接口 |
| `retrieval_engine.py` | 混合检索后端，实现 BM25、dense、RRF、rerank 和 parent section 返回 |
| `product_router.py` | 产品路由模块，识别问题涉及的产品、型号或候选手册 |
| `rerank_client.py` | rerank 服务客户端 |
| `submission_utils.py` | `[[PIC:...]]` 抽取、`<PIC>` 归一、图片数组生成、客服题清洗和最终格式化 |
| `parse_manuals.py` | 从 Markdown 手册生成结构化 section 和 retrieval chunks |
| `build_retrieval_index.py` | 根据 retrieval chunks 构建 BM25 与 FAISS 索引 |
| `generate_submission_v5.py` | 离线跑批脚本，文件名沿用历史命名，当前内容为 V6 主线 |
| `validate_delivery.py` | 交付包静态自检脚本 |
| `validate_performance.py` | 验证报告数据表生成脚本，产出产品路由、图文、入口路由、对话等验证表格 |

## 6. 默认配置与覆盖方式

默认配置集中在：

```text
config_runtime.py
```

包括：

- `/chat` Bearer Token；
- DeepSeek V4 Flash service / tech 三路二分类路由器；
- 文本请求使用 `deepseek-v4-flash`，上传图片时使用 `deepseek-v4-flash-vision-exp`；
- 硅基流动 `Qwen/Qwen3-Embedding-8B` 与 `Qwen/Qwen3-Reranker-8B`；
- `RERANK_CANDIDATE_POOL=20`，现役默认采用已验证的C20；历史实验覆盖80/20/10，其中Baseline固定查询实测候选最大34；
- 超时、并发、图片数量和图片大小限制；
- `RETURN_PARENT_SECTION=1` parent section 返回策略。

`retrieval_engine.py` 另提供未接入现役索引的实验函数 `tokenize_mixed_clean()`。它只清理结构噪声和同位置重复Token，并保留正文真实词频；必须完成固定Section标注集对照后，才能决定是否重建现役BM25元数据。

`api_server.py` 和 `llm_router.py` 启动时会调用 `apply_default_env()`，只为未设置的环境变量写入默认值。因此可以直接启动，也可以通过环境变量覆盖。

示例：

```bash
SILICONFLOW_BASE_URL="https://api.deepseek.com" \
SILICONFLOW_API_KEY="sk-..." \
SILICONFLOW_MODEL="deepseek-v4-flash" \
SILICONFLOW_VISION_MODEL="deepseek-v4-flash-vision-exp" \
./run_api.sh
```

## 10. 静态自检

提交前执行：

```bash
python validate_delivery.py
```

脚本检查：

- 必需源码、索引、手册、插图和交付文档是否存在；
- `run_api.sh`、`smoke_test.sh` 是否具备可执行权限；
- Python 源码是否可语法编译；
- 函数/类 docstring 注释覆盖率是否不低于 30%；
- 是否混入 `__pycache__`、`.bak`、运行期 trace/raw 等临时文件；
- 是否存在散落在非配置文件中的疑似密钥。

检查结果会随源码和本地运行文件变化，不在运行手册复制快照；最近一次结果及阻断项统一记录在 `04_验证报告.md`。

### 10.1 并发与超时专项回归

```powershell
$env:PYTHONUTF8 = '1'
.\.venv\Scripts\python.exe -B -m unittest discover -s tests -p "test_request_context.py" -v
```

该测试覆盖并发线程QID隔离、请求截止时间、取消事件、API 504后worker回收，以及LLM、Embedding、Rerank超时参数受剩余请求预算约束。测试使用桩响应，不访问外部模型服务。

正式检索Trace与图片API同样提供纯本地回归：

```powershell
.\.venv\Scripts\python.exe -B -m unittest discover -s tests -p "test_search_manual_trace.py" -v
.\.venv\Scripts\python.exe -B -m unittest discover -s tests -p "test_api_images.py" -v
```

前者验证正式 `search_manual` 子阶段计时、Embedding HTTP状态记录、发送模式和延迟汇总；后者验证图片ID完整性、JPG/PNG响应、404与路径穿越、图片顺序、客服隔离、旧 `answer` 兼容、网页入口和进度端点。两组均不访问外部模型服务，具体用例数以测试发现结果为准。

启动API后可访问 `http://127.0.0.1:8000/` 使用最小图文网页。真实延迟实验会访问外部模型服务，运行前必须确认外发范围；文本Trace、串行/批量/并行对照、探索性Query实验的口径与结论统一见 `06_分词与检索优化实验设计.md`。正式路径当前默认 `TEXT_QUERY_EMBED_MODE=batch`，保留 `serial` 回退，批量模式不新增关键词。

## 13. 代码注释与结构规范

本代码包采用模块化结构组织核心能力：

- API 层负责请求校验、鉴权、超时、trace、session 短历史和在线 service / tech 分类；
- Agent 层根据 `question_id` 选择客服或技术 prompt，并负责技术题检索工具、技术 prompt 和答案收束；
- 检索层负责 BM25、dense、RRF、rerank 和 parent section 返回；
- Formatter 层负责图片锚点抽取、`<PIC>` 归一和平台格式清洗。

注释覆盖率采用“有 docstring 的函数/类占全部函数/类的比例”作为自检口径。该口径比简单统计 `#` 行数更适合本工程，因为核心说明集中在模块、函数、类 docstring 和关键代码块注释中；具体检查结果统一见 `04_验证报告.md`。
